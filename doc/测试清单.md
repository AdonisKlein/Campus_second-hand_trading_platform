# 校园二手交易平台测试清单

## 1. 使用说明

本清单按照当前 `UC01`～`UC18` 和项目实际测试结构编写。每项测试只有在“操作完成 + 有结果判断断言 + 关键最终状态正确”时才算有效；仅启动程序、接口返回 2xx 或没有抛异常不算通过。

状态标记：

- `[ ]` 待执行或待补充
- `[x]` 已有自动化覆盖
- `[~]` 有部分覆盖，仍需补充独立断言或反向场景

## 2. 有效性统一标准

### 单元测试

- 测试目标是类、方法、业务规则或异常分支，不依赖完整 HTTP 流程。
- 每个测试必须使用 JUnit 断言验证返回值、抛出的异常、状态变化或依赖调用参数。
- 异常测试必须断言异常类型和稳定错误语义，不能只写 `assertDoesNotThrow`。
- 状态机测试必须同时断言前置对象、目标对象和不应变化的对象。

### 集成/API 测试

- 测试必须经过 Controller、Security、领域服务、Repository 和数据库边界。
- 每个用例至少覆盖主成功流程，以及一个备选或异常流程；权限用例必须包含反向越权。
- 必须断言 HTTP 状态、响应安全字段和数据库最终状态。
- 写请求必须验证 Session/CSRF；请求体中的 `userId`、`buyerId`、`sellerId`、`senderId`、`adminId` 被篡改时仍不能越权。
- 并发测试必须断言数据库最终唯一性和状态机结果，而不是只断言线程没有报错。

### 端到端测试

- 从真实页面或真实 HTTP 入口开始，走完一条完整业务旅程。
- 必须断言页面可见结果、接口结果和关键数据库/业务状态；不能只断言页面打开。
- 测试应使用隔离环境和数据工厂，不依赖宿主机已有数据或固定自增 ID。
- 失败时保存 HTML report、JUnit XML、截图、视频、trace、控制台日志和失败网络请求。

## 7. 执行与通过门槛

```powershell
# 后端单元、API 集成、Flyway 和 Testcontainers 门禁
cd backend
mvn verify

# 前端契约与 JavaScript 语法
cd ..\frontend
node --test tests/*.test.js
Get-ChildItem assets/js -Filter *.js | ForEach-Object { node --check $_.FullName }

# Compose E2E（需要 Docker Desktop）
cd ..\e2e
npm run test:e2e:compose

# 变更格式
cd ..
git diff --check
```

测试全部有效的判定：

- 单元测试有业务结果断言，关键异常分支被断言。
- API 测试覆盖 UC01～UC18 的主流程、备选流程和异常/越权流程，并断言数据库最终状态。
- E2E 覆盖全部 UC；一个旅程可以覆盖多个 UC，但不能只用 smoke 代替业务流程。
- Docker 可用时 MySQL 8.4 Testcontainers 不得跳过；若环境不可用，必须在报告中标记为未完成而不是通过。
- E2E 失败证据完整，且桌面端与 390px 移动端无整体横向溢出。
- `git diff --check`、全部 JS 语法、Maven 和适用的前端/E2E 门禁均通过。
