# 校园二手交易平台软件开发计划书

## 1. 项目目标

校园二手交易平台面向在校学生，支持二手商品发布、校园搜索、公开问答、私聊、购买意向、卖家选择、当面交接和内容治理。当前版本采用模块化单体，不在没有独立伸缩或部署需求时拆分微服务。

当前验收基线为 `REQ01`～`REQ18`、`UC01`～`UC18`。业务术语、interface 和安全不变量分别以 `CONTEXT.md`、`docs/ai/PROJECT_CONTEXT.md` 和 `AGENTS.md` 为准。

## 2. 技术与交付范围

| 交付项 | 位置 | 说明 |
| --- | --- | --- |

| 自动化测试 | `backend/src/test/`、`frontend/tests/`、`e2e/` | 单元、API、MySQL 并发、前端契约和 Playwright E2E。 |

## 3. 当前产品范围

### 已实现并纳入验收

- UC01～UC04：邮箱验证注册、Session 登录退出、密码重置和个人资料。
- UC05～UC08：校园搜索、受控单图商品发布、卖家维护和安全商品详情。
- UC09～UC10：公开问答、买卖双方私聊、未读与屏蔽。
- UC11～UC14：非独占购买意向、卖家选择、预留、当面交接和交易工作台。
- UC15～UC17：学生举报、管理员治理和用户/商品/留言管理。
- UC18：Session、CSRF、角色、资源归属和会话撤销安全边界。
- Docker Compose、Mailpit 本地邮件、MySQL 8.4、CI、GHCR 候选镜像和 Kind 部署验证。

### 当前明确不实现

- 在线支付、退款、物流配送和评价体系。
- 多图商品、图片私聊消息、结构化报价。
- WebSocket/SSE 实时消息；当前文本私聊使用短轮询。
- Windows、Android 和 iOS 原生客户端。
- Redis、消息队列、对象存储和微服务拆分。

这些能力只有在建立独立领域 interface、状态机、权限规则和测试方案后才能进入开发，不能用纯前端状态或自由文本伪装完成。

## 6. 开发规则

### 身份与安全

- Web 身份只相信服务端 Session；请求体中的身份 ID 永远不是授权依据。
- 所有 Web 写请求保留 CSRF，前端统一通过 `api.js` 的 `request()`。
- 后端通过 `CurrentActorService` 获取当前用户，并检查角色、账号状态和资源归属。
- 不提交 `deploy/.env`、真实密码、验证码 pepper、SMTP 密钥或其他本地凭据。

### 领域边界

- 交易状态修改统一经过 `TradingService`，Controller 和前端不复制状态规则。
- 商品交易状态与管理员审核状态分离。
- 公开问答与私聊分离，管理员不能读取学生私聊正文。
- 举报处理只允许追加审计，不覆盖或删除最终处理历史。

### 数据库与部署

- 数据库结构只通过新的 Flyway 迁移演进；Hibernate 保持 `validate`。
- `database/schema.sql` 只创建空数据库，不能在其中维护业务表。
- Docker 和 Kubernetes 敏感配置运行时注入，不写入镜像或仓库。
- 商品图片单机使用持久卷；多实例前替换对象存储 adapter。

## 7. 质量保证计划

### 每个业务轮次

1. 根据用例补充后端规则和反向权限测试。
2. interface 变化时同步 Postman、项目上下文和追溯矩阵。
3. 验证桌面端和 390px 移动端，无整体横向溢出。
4. 运行 Maven、前端测试、全部 JS 语法和 `git diff --check`。
5. 对共享行为扩大回归范围，并完成独立 P0/P1 审查。
6. 更新 `docs/ai/WORKLOG.md`，记录完成内容、验证证据、提交号和遗留项。

### 常用门禁

```powershell
cd backend
mvn verify

cd ..\frontend
node --test tests/*.test.js
Get-ChildItem assets/js -Filter *.js | ForEach-Object { node --check $_.FullName }

cd ..
git diff --check
```

Docker 可用时必须执行真实 MySQL 8.4 Testcontainers；完整发布候选还需通过 Compose E2E 和 Kind 部署门禁。

## 8. 风险管理

| 风险 | 控制措施 |
| --- | --- |
| 客户端身份伪造 | Session 当前身份、CSRF、角色和资源归属反向测试。 |
| 并发选择多个买家 | 商品行锁、`TradingService` 状态机和 MySQL 并发测试。 |
| H2 与 MySQL 行为差异 | 真实 MySQL 8.4 Testcontainers 迁移与查询门禁。 |
| 图片攻击或跨用户引用 | 内容解码、尺寸/配额限制、重编码和 owner 路径校验。 |
| 私聊泄漏 | 随机会话号、参与者授权、公开留言接口隔离。 |
| 举报重复处理 | 唯一约束、行锁、最终状态和追加式审计。 |
| 文档与实现漂移 | UC/REQ/模型/测试追溯，interface 变化同步更新文档。 |
| 凭据泄漏 | 示例变量、Git 忽略文件、CI/Kubernetes Secret 注入。 |

## 9. 验收标准

- UC01～UC18 的主流程、异常流程和安全边界有可追溯证据。
- 购买意向不独占商品，只有卖家接受后形成预留，只有买家确认交接后商品售出。
- 普通学生不能操作他人资源或管理员能力，管理员不能读取学生私聊正文。
- Flyway 可从空 MySQL 8.4 建库并通过 Hibernate validate。
- Maven、前端契约、JS 语法、`git diff --check` 和适用的 E2E/部署门禁通过。
- 桌面和 390px 移动页面无整体横向溢出，关键状态反馈清晰。
- 文档、Postman、项目上下文、追溯矩阵和工作日志保持同步。
