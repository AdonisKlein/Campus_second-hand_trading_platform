# 校园二手交易平台软件详细设计说明书

## 后端分层

后端包根为 `com.campus.secondhand`。Controller 负责 HTTP 输入输出，领域服务集中业务规则，Repository 负责查询和锁，实体映射 Flyway 建立的表结构。写接口不从请求体取得操作者身份，统一使用 `CurrentActorService`。

| 包 | 关键类或 interface | 责任 |
|---|---|---|
| `security` | `CurrentActorService`、`SecurityConfig` | Session、CSRF、当前身份和安全策略。 |
| `user` | `AuthController`、`VerificationService` | 注册、登录、验证码、资料、密码重置。 |
| `item` | `SellerInventory`、`ProductDetailService` | 商品归属、编辑、下架、详情投影。 |
| `media` | `ProductImages`、`FileSystemProductImages` | 图片内容验证、重新编码和持久化。 |
| `search` | `CampusSearch`、`JpaCampusSearch` | 多关键词、筛选、排序与安全用户投影。 |
| `order` | `TradingService`、`TradeDesk` | 购买意向、预留、取消、完成与工作台。 |
| `chat` | `DirectChatService` | 会话、消息、未读、屏蔽和读取游标。 |
| `report` | `ContentGovernanceService` | 举报、管理员治理与追加式审计。 |

## 认证与授权

`/auth/login` 建立服务端 Session，`/auth/logout` 撤销当前会话，`/auth/csrf` 提供写请求所需令牌。`api.js` 通过 `request()` 统一携带 Cookie 与 CSRF。服务端只以当前 Session 推导身份，再检查资源归属；管理员操作还会检查真实管理员角色和账号状态。

## 商品与图片

`Item` 保存标题、分类、价格、描述、校园区域、标签、卖家、交易状态与审核状态。图片不再由前端提交任意 URL；`ProductImageController` 接收文件，`ProductImages` 验证 JPG/PNG、大小和像素，清除元数据后以平台路径保存。商品详情投影包含安全卖家摘要、当前用户的购买意向、可执行动作和同卖家在售商品。

## 交易状态机

`TradingService.requestPurchase(actorId, itemId)` 创建 `PURCHASE_REQUESTED` 意向，不改变商品在售状态。`perform(actorId, orderId, action)` 是唯一状态变更入口：卖家 `ACCEPT` 后订单为 `WAITING_HANDOVER`、商品为 `RESERVED`；买家 `COMPLETE` 后订单为 `COMPLETED`、商品为 `SOLD`。取消和超时按同一服务释放预留或关闭意向，返回 `allowedActions` 供前端渲染。

## 私聊、留言与治理

公开留言按商品展示，发送者只能修改或删除自己的内容。私聊会话按商品、买家和卖家唯一，消息以 sequence 游标分页，管理员不能读取正文。举报支持商品、留言和用户三种对象；管理员处置使用行锁并追加 `report_actions` 审计。

## 数据库与前端

Flyway V1 建立用户、商品、留言、订单、验证码和 Session 基线；V2 增加校园搜索字段；V3 增加举报和审计；V4 增加私聊；V5 增加购买意向工作流。Hibernate 配置为 `validate`，不替代迁移建表。

`api.js` 是 Session、CSRF 与请求的唯一入口。`main.js` 管理校园搜索，`detail.js` 负责商品详情、留言、私聊和购买意向，`orders.js` 渲染订单工作台，`chat.js` 渲染私聊，`admin.js` 处理管理与举报队列。页面只根据服务端返回的投影和 `allowedActions` 展示可操作状态。

## 验证与边界

后端测试包括身份伪造字段的反向用例，确保即使请求体出现 `buyerId`、`sellerId` 或 `adminId`，服务端仍只信任 Session。当前未实现支付、物流、评价、多图、图片消息和 WebSocket/SSE；Web 的正式身份方案始终是服务端 Session。
