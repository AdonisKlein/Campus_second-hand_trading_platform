# 校园二手交易平台 UI 视觉与交互设计方案

> 状态：当前 Web 设计基线
>
> 适用范围：REQ01～REQ18 / UC01～UC08
>
> 参考页：`doc/ui-style-preview.html` 仅用于颜色与组件预览，不是业务页面模板

## 1. 设计目标

平台面向需要重复浏览、发布、沟通和处理交易的校园用户。界面应安静、清晰、任务优先：进入页面后直接展示搜索、数据、表单或管理任务，不使用品牌口号横幅、欢迎介绍、功能宣传、发布技巧侧栏或整块交易流程教学。

设计关键词：

- 可信，但不过度正式。
- 年轻，但不幼稚。
- 信息密度适中，方便快速扫描。
- 桌面高效，移动端单手可操作。
- 操作结果和失败原因始终可见。

## 2. 视觉系统

### 色彩

| 用途 | 建议色 | 使用规则 |
| --- | --- | --- |
| 品牌与主操作 | 航空蓝 `#2563EB` | 顶栏品牌、主要按钮、选中和焦点。 |
| 交易行动与价格 | 活力黄 `#FACC15` | 价格、发布入口和少量关键行动，不作大面积背景。 |
| 成功 | `#16A34A` | 完成、有效、恢复等正向状态。 |
| 警告 | `#D97706` | 即将超时、等待处理和需确认状态。 |
| 错误/危险 | `#DC2626` | 删除、禁用、治理、失败和不可逆操作。 |
| 页面背景 | 冷灰 `#F8FAFC` | 保持业务内容清晰，不使用装饰性渐变或光斑。 |
| 正文 | `#1F2937` | 主要文字。 |
| 次要文字 | `#64748B` | 时间、辅助信息和次要状态。 |

颜色不能作为唯一状态信号；状态必须同时使用文字或图标。文本与背景满足可读对比度。

### 字体与尺寸

- 中文优先使用系统无衬线字体：`Microsoft YaHei`、`PingFang SC`、`Noto Sans SC`。
- 正文通常为 14～16px，紧凑工具面板可使用 13～14px。
- 页面 H1 通常为 24～30px；卡片和侧栏标题保持 16～20px。
- 不按视口宽度缩放字体，不使用负字间距。

### 间距、圆角与阴影

- 使用 4px 基础网格，常用间距为 8、12、16、24、32px。
- 卡片圆角不超过 8px；按钮、输入框和状态标签保持统一尺度。
- 页面分区优先使用留白、边框和全宽区域，不把每个区块都做成悬浮卡片。
- 不在卡片内部再嵌套视觉卡片。

## 3. 响应式框架

### 桌面端

- 顶栏提供品牌、搜索和主要导航，管理员入口默认隐藏。
- 页面主体使用受约束的内容宽度；列表、工作台和管理页优先服务扫描与批量判断。
- 首页无商品分类侧栏。搜索前显示最新商品，提交后才展示商品/用户切换、排序和筛选。
- 商品详情采用图片、交易信息、卖家摘要和公开问答的任务布局。
- 私聊采用会话列表、聊天房间、商品/交易上下文三栏。
- 订单工作台按买卖视角、阶段和商品分组组织。

### 移动端

- 以 390px 为主要验收宽度，同时检查 320px 极窄场景。
- 使用固定底部导航承载高频入口，数量和文字不得导致换行或横向溢出。
- 商品详情图片优先，关键交易动作固定在底部但不得遮挡正文。
- 私聊使用“会话列表 → 聊天房间”的两级布局，不强行压缩桌面三栏。
- 筛选、交易详情和确认操作使用抽屉或模态层，关闭路径清晰。
- 固定工具栏、按钮、计数器和图片区域使用稳定尺寸，动态文字不能推动整体布局跳动。

## 4. 页面设计

### 首页与搜索（UC02）

- 首屏直接提供搜索和最新在售商品。
- 搜索提交后出现商品/用户切换、排序、价格、区域和标签筛选。
- 商品卡突出真实图片、标题、价格、区域、标签和卖家摘要。
- 用户结果只展示安全公开资料。
- 加载、空结果和网络失败在结果区域内显示，不使用浏览器 `alert`。

### 注册、登录和个人中心（UC01）

- 页面保持单任务布局，不加入欢迎宣传或功能介绍侧栏。
- 注册、登录、找回密码用明确标签或分段控件切换。
- 验证码发送状态、倒计时、错误和成功跳转可见。
- 登录成功、注册完成和密码重置提示为一次性反馈，刷新后不重复。

### 发布与我的发布（UC03）

- 发布表单按图片、基本信息、区域和标签组织。
- 图片区域提供选择、预览、替换、移除、上传中和失败恢复状态。
- 标签使用可选控件而不是自由文本堆叠，最多 4 个。
- “我的发布”清楚区分交易状态、卖家展示状态和管理员审核状态。
- 编辑、下架和重新上架只在服务端允许时出现或启用。

### 商品详情（UC02、UC04～UC05）

- 图片是首要内容，价格、状态和交易按钮紧邻展示。
- 卖家摘要只包含昵称、校园区域、信用、活跃时间和在售数量。
- 游客、买家、已有意向买家和卖家看到不同动作。
- 公开问答与私聊入口在视觉和文字上严格区分。
- 同卖家商品和校园交易安全提醒属于辅助内容，不抢占主任务。

### 私聊消息（UC04）

- 会话列表支持搜索、未读优先和分页。
- 聊天历史按 sequence 加载更早内容，发送失败消息提供重试。
- 明确展示连接、加载、屏蔽和发送失败状态。
- 商品与订单上下文可访问，但不伪装结构化报价或支付能力。
- 举报、屏蔽等治理操作使用图标加清晰标签，并要求必要确认。

### 订单工作台（UC05～UC06）

- 使用分段控件切换“我买到的 / 我卖出的”，使用阶段筛选组织记录。
- 卖家视角按商品分组购买意向，支持比较买家公开信用。
- 买家视角突出当前阶段、剩余时间、时间线和关闭原因。
- 页面只渲染后端返回的 `allowedActions`，不自行推导交易状态。
- 接受、拒绝、取消、完成等动作使用页面内确认框并展示最终结果。

### 我的举报与管理中心（UC07～UC08）

- “我的举报”按处理中、成立和驳回展示状态、对象快照与管理员说明。
- 管理中心采用紧凑侧栏、筛选、表格/列表和详情面板，便于持续处理任务。
- 举报处理必须同时展示对象类型、快照、当前状态、可用措施和审计信息。
- 危险操作使用明确的危险色和确认，不使用模糊图标或只靠颜色区分。

## 5. 组件与交互规则

### 控件选择

- 搜索、筛选和排序使用输入框、选择菜单和分段控件。
- 二元设置使用复选框或开关。
- 数值使用数字输入、步进器或滑块。
- 工具操作优先使用熟悉的图标；不熟悉图标提供 tooltip。
- 明确命令使用文字或图标加文字按钮。

### 表单

- 所有字段具有可见标签，必填、格式和长度要求在相邻位置表达。
- 校验信息出现在字段附近，提交结果使用 `role=status` 或等价可访问反馈。
- 提交期间按钮防重复，失败后保留用户输入并允许重试。
- 安全或隐私影响只用简短、必要的提示说明。

### 状态反馈

每个数据页面至少覆盖：

- 初次加载。
- 加载成功。
- 空数据。
- 输入无结果。
- 网络失败和重试。
- 未登录/无权限。
- 写操作进行中、成功和失败。

确认框不能依赖浏览器原生 `alert`/`confirm` 承担复杂业务反馈。

### 图像与图标

- 商品图片应展示真实商品；加载失败使用统一占位图。
- 图片容器使用稳定 `aspect-ratio` 和裁切规则，避免列表跳动。
- 使用项目现有图标库或一致的系统图标，不手工混用不同风格 SVG。
- 不使用装饰性渐变球、光斑或与任务无关的插画。

## 6. 可访问性

- 键盘可以访问主要导航、表单、对话框和菜单，焦点样式清晰。
- 图标按钮具有 `aria-label`，图片具有符合用途的替代文本。
- 对话框打开后焦点进入，关闭后返回触发元素。
- 动态状态使用适当的 live region，不仅依赖视觉变化。
- 触控目标尺寸适合移动端，固定底栏不遮挡页面内容。

## 7. 安全与身份体验

- 管理入口在 HTML 默认 `hidden`，只有 `/users/me` 返回 ADMIN 后显示。
- 游客点击受保护操作时留在当前页面确认，确认后登录并返回原目标。
- 本地用户对象仅用于展示；任何可见/隐藏逻辑都不替代后端授权。
- 401 后清理本地渲染身份并给出重新登录入口；403 明确区分权限或 CSRF 问题。
- 禁用或会话撤销提示清楚，但不泄漏内部认证细节。

## 8. 验收标准

- 实际业务页直接进入搜索、数据、表单或管理任务，无宣传型页面结构。
- 1440px 桌面端和 390px 移动端无整体横向溢出；必要时补测 768px 和 320px。
- 最长状态文字、价格、昵称和按钮文案不溢出容器或遮挡相邻内容。
- 商品详情、订单、私聊、举报和管理中心的关键状态均有可见反馈。
- 管理入口默认隐藏，受保护写请求统一经过 `api.js`。
- `frontend/tests/ui-design-contract.test.js`、Session 竞态测试和全部 JS 语法通过。
- 使用真实页面截图检查桌面/移动布局，而不是只检查视觉预览页。
