

### 工作项 1：测试基础骨架

建立：

```
backend/src/test/java/.../unit/
backend/src/test/java/.../api/
backend/src/test/java/.../mysql/
e2e/
scripts/ci/
test-results/
```

配置：

- Surefire：执行 `*Test`
- Failsafe：执行 `*IT`
- Playwright：执行 E2E
- 测试数据工厂
- 固定 `Clock`
- XML、HTML、JSON、Markdown 报告汇总

注意：空目录不能被 Git 保存。不要只建空目录，应该放真正的 Smoke Test。

验收命令：

```
cd backend
mvn test
mvn verify

cd ../e2e
npm ci
npm run test:e2e
```

### 工作项 2：CI 测试门禁骨架

初期流水线先执行现有测试：

```
backend-unit
backend-api
frontend-static
upload-reports
```

要求：

- `pull_request` 和 `push` 触发。
- Java 使用 JDK 25。
- 测试失败，Job 必须失败。
- 报告上传使用 `if: always()`。
- 不使用 `continue-on-error`。
- 暂不推送镜像，不部署。

### 工作项 3：高优先级单元测试

范围：

- UC01：验证码与注册事务。
- UC02：登录规则、锁定和认证状态。
- UC03：密码重置和旧认证失效。
- UC04：个人资料修改规则。
- UC05：搜索关键词、价格、排序。
- UC15/16：举报和治理规则。
- UC17：管理员管理规则。
- Security：当前身份和权限撤销。

需要注意：

- Session/CSRF 更适合集成测试。
- `CurrentActorService` 可以做单元测试。
- `SecurityFilterChain` 应通过 MockMvc 集成测试。

重要修正：

“同商品并发购买”不应该断言只有一个买家能提交意向，因为当前交易规则允许多人提交非独占购买意向。

真正需要测试的是：

```
两个买家均成功提交意向
→ 卖家并发接受两条意向
→ 最多一条进入 WAITING_HANDOVER
→ 商品最多形成一个 RESERVED
```

### 工作项 6：完整 CI 与版本镜像

最终流水线：

```
unit
→ api-integration
→ frontend-static
→ candidate-images
→ compose-e2e
→ publish-images
```

仅 `main` Push 允许推送 GHCR；PR 只能构建和测试，不能发布。

镜像标签建议增加运行编号，避免短 SHA 极小概率冲突：

```
ghcr.io/adonisklein/campus-backend:2026-123-sha-ab4e3fd
ghcr.io/adonisklein/campus-web:2026-123-sha-ab4e3fd
```

也可以同时附加完整 Git SHA 标签，但不能只使用 `latest`。

### 工作项 7：Kubernetes

Backend：

### 工作项 8：部署和证据

流程：

```
创建Kind
→ 加载/拉取版本镜像
→ kubectl apply -k
→ kubectl rollout status
→ 检查Pod
→ HTTP健康检查
→ 保存kubectl describe/logs
```

需要注意：GitHub Actions 中的 Kind 是临时集群，Job 完成后会销毁。因此它证明的是“可以自动部署到 Kubernetes”，不是长期在线的生产环境。

课程展示可以同时保留：

- GitHub Actions 中的自动 Kind 部署记录。
- 本机 Docker Desktop Kubernetes 或 Kind 的运行截图。
- `kubectl get pods,svc` 输出。
- 成功和失败两次流水线链接。

## 最终结论

建议实际执行顺序调整为：

1. 测试骨架和报告。
2. GitHub Actions 测试门禁。
3. 高优先级单元测试。
4. API/MySQL 集成测试。
5. Playwright E2E。
6. 候选镜像、完整 CI 和 GHCR。
7. Kubernetes 清单。
8. Kind 部署、冒烟测试和成功/失败验收记录。

这个顺序依赖关系更合理，也能保证从第二项开始，每次后续开发都会被 CI 自动检查。
