# 从对象级顺序图和系统顺序图生成测试用例

## 1. 文档目的

本文说明本项目如何把对象级顺序图和系统顺序图（`SYS-SEQ01`～`SYS-SEQ18`）转换为可执行测试用例。对象级顺序图指导单元测试；系统顺序图指导运行后端容器的系统测试。当前模块化单体不单独要求组件级集成测试，前后端 GUI 测试属于增强项验收测试。

测试实现必须对照《业务场景（用例）清单》和《需求追溯矩阵》，不能只以 Controller 返回 2xx 或页面没有报错作为通过依据。

## 2. 转换规则

| 模型元素 | 测试中的对应物 | 必须验证的内容 |
| --- | --- | --- |
| 参与者 | 测试数据工厂和 Session Cookie | 当前身份由服务端 Session 得到，不能使用请求体中的身份 ID |
| 系统边界 | 后端容器 HTTP 入口 | 请求路径、HTTP 方法、认证和 CSRF 过滤器正确 |
| 系统事件 | MockMvc 请求或真实 HTTP 请求 | 请求参数、JSON、文件和请求头符合接口契约 |
| 系统返回 | HTTP 状态和 JSON 投影 | 成功/失败状态、稳定错误消息、安全字段 |
| 对象级消息 | 单元测试中的 Service/Entity/Mock | 方法输入输出、异常分支和对象状态变化正确 |
| 领域服务调用 | 系统测试中的 Service + Repository + 数据库 | 业务规则集中执行，资源归属和角色校验生效 |
| 状态转换 | 持久化实体最终状态 | 目标对象变化正确，不应变化的对象保持不变 |
| 备选/异常分支 | 反向测试或非法请求测试 | 未登录、无 CSRF、越权、重复、过期、并发等被拒绝 |
| 外部参与者/适配器 | Mockito、Testcontainers 或 Mailpit | 邮件、MySQL、图片存储等边界行为可观察且可复现 |

## 3. 测试用例生成模板

每张系统顺序图至少生成以下测试字段：

1. **测试编号**：系统测试对应 `SYS-TCxx`（代码中的 `*ApiIT` 为实现入口）。对象级规则另对应 `UNIT-TCxx`。
2. **参与者身份**：游客、学生、买家、卖家或管理员，以及 Session 来源。
3. **前置数据**：用户、商品、订单、留言、举报和当前状态。
4. **事件序列**：按图中从上到下的系统调用顺序发送请求。
5. **主流程断言**：每一步 HTTP 响应、返回字段和最终数据库状态。
6. **备选/异常断言**：至少一个图中异常分支，权限用例必须有反向主体。
7. **不变量断言**：例如商品仍在售、订单快照不变、邮箱不返回、审计记录追加。

## 5. 完整示例：SYS-SEQ11 买家提交购买意向

### 5.1 从图读取测试契约

- 参与者：学生用户，在本次交易中临时成为买家。
- 系统事件：买家提交“我想要”，系统创建购买意向。
- 返回结果：返回订单/意向记录及其状态。
- 关键状态：订单为 `PURCHASE_REQUESTED`，商品仍为 `ON_SALE`。
- 异常分支：卖家本人不能购买；重复有效意向不能再次创建；缺少 CSRF 不能写入。

### 5.2 测试步骤

1. 创建卖家、买家和 `ON_SALE + VISIBLE` 商品。
2. 使用买家邮箱登录，取得 Session Cookie。
3. 使用该 Session 和 CSRF 发送 `POST /orders`，请求体只包含 `itemId`。
4. 断言 HTTP 成功、返回的 `buyerId` 等于 Session 用户，而不是请求体字段。
5. 查询数据库，断言订单状态为 `PURCHASE_REQUESTED`，商品状态仍为 `ON_SALE`。
6. 重复发送同一请求，断言业务失败且数据库仍只有一条有效意向。
7. 用卖家 Session 发送同一请求，断言业务失败。
8. 去掉 CSRF 或伪造 `buyerId`，断言请求被拒绝，原订单和商品状态不变。

### 5.3 建模作用

如果实现错误地在“提交购买意向”事件中把商品改为 `RESERVED`，第 5 步会失败；如果 Controller 信任请求体中的 `buyerId`，第 4 步或第 8 步会失败；如果没有唯一有效意向约束，第 6 步会失败。因此，系统顺序图中的事件顺序和状态说明直接形成了代码的可执行验收标准。

## 6. 完整示例：SYS-SEQ16 管理员治理举报

测试必须覆盖两条结果分支：

- **成立**：管理员 Session 处理举报，治理措施与对象匹配（商品下架、留言移除或用户禁用），并追加一条 `report_actions` 审计记录。
- **驳回**：举报状态变为 `DISMISSED`，对象状态不能改变，仍追加审计记录。

反向测试使用普通学生 Session 调用管理员接口，必须返回 403；再次处理已结束举报，必须失败且不能追加第二条最终处理记录。`MySqlConcurrencyIT` 用两个并发管理员请求验证行锁只允许一个最终处理结果。

## 7. 其余用例测试用例

以下用例按照对应系统顺序图逐项执行。每项的“系统操作”就是图中参与者发送给系统的操作；断言同时检查返回结果和必要的持久化状态。

| 用例 | 基本流程测试 | 扩展/异常流程测试 | 关键建模验证点 |
| --- | --- | --- | --- |
| UC01 注册验证 | 发送注册验证码，提交验证码、密码和资料，断言账号 `ACTIVE`、Session 建立 | 已注册邮箱、错误/过期验证码、频率超限不得创建账号 | 验证码用途和注册事件顺序正确 |
| UC02 登录退出 | 登录，读取 `/users/me`，退出后再次读取 | 错误密码、禁用账号、认证版本变化使旧 Session 失效 | Session 建立/撤销与参与者身份一致 |
| UC03 重置密码 | 发送重置验证码，提交新密码并用新密码登录 | 注册验证码冒充重置验证码、重复消费、旧密码登录失败 | 重置事件必须撤销旧认证状态 |
| UC04 资料维护 | 读取本人资料，修改昵称、联系方式和校园区域，断言公开投影更新 | 未登录、非法区域、提交他人字段不得修改安全资料 | 资料更新只改变允许对象字段 |
| UC05 搜索筛选 | 游客用多关键词搜索商品，再切换用户范围并应用筛选/排序 | 超过 8 个词截断、价格范围非法、用户结果不得含邮箱手机号 | 搜索操作映射到安全公开投影 |
| UC06 发布图片商品 | 上传 JPG/PNG，提交标题、价格、区域和标签，断言商品在售可见 | 非图片、超 5MB、超像素、跨 owner 图片路径和无 CSRF 失败 | 图片适配器和商品创建顺序正确 |
| UC07 商品维护 | 查看本人发布，编辑资料，执行卖家下架后重新上架 | 非 owner、预留/售出商品、管理员已移除时操作失败 | 卖家状态与交易/审核状态分离 |
| UC08 商品详情 | 游客、买家和卖家分别读取详情，断言安全卖家摘要和允许动作 | 不可见商品不泄漏；卖家不能购买自己的商品 | 同一系统操作因参与者身份返回不同动作集合 |
| UC09 公开问答 | 读取留言，登录后发布、修改并删除本人留言 | 未登录发布、修改他人、不可见商品留言失败 | 公开留言与私聊正文严格隔离 |
| UC10 私聊沟通 | 买家从详情创建会话，发送消息，卖家读取历史并标记已读 | 陌生用户读取、屏蔽后发送、管理员读取正文失败 | 会话唯一、sequence 单调、未读游标前进 |
| UC12 处理购买意向 | 卖家读取意向并接受一条，断言订单待交接、商品预留 | 拒绝、过期、非卖家处理和并发接受失败 | 接受事件触发唯一预留及其他意向关闭 |
| UC13 当面交易 | 买家确认取货，断言订单完成、商品售出 | 买家/卖家取消、超时释放预留、非参与者和重复完成失败 | 状态机只允许图中合法迁移 |
| UC14 交易工作台 | 分别以买入/卖出视角查看阶段、分组、时间线和待办 | 读取他人订单、非法阶段参数和隐私字段失败 | 工作台是领域服务返回的完整投影 |
| UC15 学生举报 | 举报商品/留言/用户，进入“我的举报”查看处理结果 | 自报、重复、24 小时超过 20 条、查看他人记录失败 | 举报对象快照与举报人 Session 一致 |
| UC17 管理内容 | 管理员查看用户、商品、留言并执行允许的管理操作 | 普通学生访问管理员接口 403；管理操作不得覆盖交易状态 | 管理员权限和交易状态机边界独立 |

UC11、UC16、UC18 已在前文分别以购买意向、治理举报和安全操作为例；加上本表即可覆盖 UC01～UC18 的基本流程与扩展流程。

## 8. 完整示例：SYS-SEQ18 一次受保护业务操作

以修改本人商品为例，沿图验证：

1. 无 Session 请求被拒绝。
2. 有 Session 但无 CSRF 请求被拒绝。
3. 合法 owner Session + CSRF 请求成功。
4. 非 owner Session + CSRF 请求被拒绝。
5. 请求体增加伪造 `sellerId` 不改变真实 owner。
6. 账号禁用或认证版本递增后，旧 Session 不能继续写入。

该测试说明安全控制是所有业务顺序图的共同前置条件，而不是某个页面的附加逻辑。
