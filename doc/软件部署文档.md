# 校园二手交易平台本地部署与运行文档

## 1. 文档目标

本文说明如何在 Windows 开发机上从全新数据库运行当前项目。推荐使用 Docker Desktop；需要调试 Java 代码时，再使用“本机 MySQL + Maven + 静态前端”的开发方式。

项目当前使用 MySQL 8.4、Java 25、Spring Boot 3.5、Flyway、Spring Session JDBC 和 Nginx。数据库没有历史升级负担：全新环境只创建空数据库，后端启动时由 Flyway 建立并校验全部表。

> 不要把真实 MySQL 密码、SMTP 密码或 `VERIFICATION_PEPPER` 写进 Git 跟踪文件。Docker 凭据只保存在被忽略的 `deploy/.env`；本机开发凭据使用当前终端环境变量或 IDE 的 Run Configuration。

## 2. 方式一：Docker 一键运行（推荐）

### 2.1 准备环境

安装并启动 Docker Desktop。在项目根目录打开 PowerShell，确认 Docker 引擎可用：

```powershell
docker version
docker compose version
```

如果 `docker version` 只有 Client、没有 Server，请先启动 Docker Desktop，等待状态变为 Running。

### 2.2 创建本机配置

从示例创建本机专用配置：

```powershell
Copy-Item deploy/.env.example deploy/.env
```

生成两个随机值，可分别作为数据库应用密码和验证码 pepper：

```powershell
[Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(24))
[Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

编辑 `deploy/.env`，至少填写：

```dotenv
MYSQL_ROOT_PASSWORD=仅供本机Docker数据库使用的强密码
MYSQL_PASSWORD=campus应用账号的强密码
VERIFICATION_PEPPER=至少32字节的随机值
PUBLIC_ORIGIN=http://localhost
SESSION_COOKIE_SECURE=false
WEB_PORT=80
```

邮件参数可以先保留占位值。邮件不可用不会阻止网站启动，但发送注册/找回密码验证码会失败。需要验证邮件流程时再填写可用 SMTP 参数。

### 2.3 构建并启动

在项目根目录执行：

```powershell
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build
docker compose --env-file deploy/.env -f deploy/docker-compose.yml ps
```

预期 `mysql`、`backend`、`web` 均为 `Up`，MySQL 和后端显示 `healthy`。首次构建需要下载基础镜像和 Maven 依赖，耗时会比后续启动长。

访问地址：

```text
网站：http://localhost
后端存活检查：http://localhost/api/actuator/health/liveness
```

健康接口返回 `{"status":"UP"}` 表示后端可用。

### 2.4 可选：导入本地演示数据

只允许在**从未写入用户或商品的全新本地数据库**执行一次，禁止用于正式环境。脚本发现业务数据会主动终止，不会覆盖已有账号或商品。

```powershell
docker compose --env-file deploy/.env -f deploy/docker-compose.yml cp database/seed.sql mysql:/tmp/seed.sql
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec -T mysql sh -lc 'mysql --default-character-set=utf8mb4 -uroot -p"$MYSQL_ROOT_PASSWORD" < /tmp/seed.sql'
```

演示账号：

| 身份 | 邮箱 | 密码 |
|---|---|---|
| 管理员 | `admin@example.com` | `abc123` |
| 学生 Alice | `alice@example.com` | `abc123` |
| 学生 Bob | `bob@example.com` | `abc123` |

这些都是公开的本地演示凭据，绝不能用于正式部署。

### 2.5 日常命令

```powershell
# 查看服务状态
docker compose --env-file deploy/.env -f deploy/docker-compose.yml ps

# 查看最近日志
docker compose --env-file deploy/.env -f deploy/docker-compose.yml logs --tail 200 backend

# 持续查看后端日志，Ctrl+C 只退出日志，不停止容器
docker compose --env-file deploy/.env -f deploy/docker-compose.yml logs -f backend

# 重新构建并应用代码修改
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build

# 停止并删除容器，保留数据库和上传图片
docker compose --env-file deploy/.env -f deploy/docker-compose.yml down

# 再次启动
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d
```

不要随意执行带 `--volumes` 的 `down`，它会删除本地数据库和上传图片。确实需要彻底重建空环境时，应先确认数据不再需要并做好备份。

## 3. 方式二：本机开发运行

这种方式适合在 IDE 中断点调试后端。数据库使用本机 MySQL，前端使用 Python 静态服务器。

### 3.1 安装并检查依赖

需要：

- JDK 25
- Maven 3.9 或以上
- MySQL 8.4（兼容 MySQL 8.x）
- Python 3（也可以使用其他静态文件服务器）
- Node.js（只在执行前端语法和契约测试时需要）

Windows 安装 JDK 25：

```powershell
winget install --id EclipseAdoptium.Temurin.25.JDK --exact
```

重新打开 PowerShell 后检查：

```powershell
java -version
mvn -version
mysql --version
python --version
node --version
```

`mvn -version` 显示的 Java home 也必须指向 JDK 25。若只安装了 JDK 24，可在兼容验收时执行 `mvn "-Djava.version=24" test`，但项目正式目标版本仍是 25。

### 3.2 创建空数据库

`database/schema.sql` 只负责创建空的 `campus_secondhand` 数据库，数据表由 Flyway 创建。PowerShell 不支持 Bash 风格的 `<` 外部程序重定向，推荐进入 MySQL 后使用 `source`：

```powershell
mysql -u root -p
```

```sql
source D:/newdir/cc/Campus_second-hand_trading_platform/database/schema.sql;
exit;
```

请把路径换成你实际克隆项目的位置，并使用正斜杠。也可以在 PowerShell 里交给 `cmd` 执行：

```powershell
cmd /c "mysql -u root -p < database\schema.sql"
```

此时只有数据库，没有业务表；第一次启动后端时 Flyway 会自动执行 `backend/src/main/resources/db/migration/` 下的迁移。

### 3.3 设置当前终端的后端环境变量

Spring Boot 不会自动读取仓库中的 `.env.example`。在启动后端的**同一个 PowerShell 窗口**设置：

```powershell
$env:DB_URL='jdbc:mysql://localhost:3306/campus_secondhand?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai'
$env:DB_USERNAME='root'
$env:DB_PASSWORD='你的本机MySQL密码'
$env:VERIFICATION_PEPPER=[Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
$env:CORS_ALLOWED_ORIGINS='http://localhost:5500,http://127.0.0.1:5500'
$env:SESSION_COOKIE_SECURE='false'
$env:UPLOAD_DIR='uploads'
```

需要真实邮件时再设置：

```powershell
$env:MAIL_HOST='你的SMTP服务器'
$env:MAIL_PORT='587'
$env:MAIL_USERNAME='你的SMTP账号'
$env:MAIL_PASSWORD='你的SMTP密码或授权码'
```

在 IntelliJ IDEA 中运行时，将同名变量填写到 Run/Debug Configuration 的 Environment variables，不要修改并提交 `application.yml` 中的密码。

### 3.4 启动后端

```powershell
Set-Location backend
mvn spring-boot:run
```

看到 Spring Boot 启动完成后，在另一个 PowerShell 检查：

```powershell
Invoke-RestMethod http://localhost:8080/api/actuator/health/liveness
```

返回 `status = UP` 即成功。启动过程中 Flyway 会建立表，Hibernate 只做 `validate`，不会偷偷修改结构。

### 3.5 启动前端

另开一个 PowerShell：

```powershell
Set-Location frontend
python -m http.server 5500
```

访问 `http://localhost:5500/`。当页面运行在 5500 端口时，`frontend/assets/js/api.js` 会自动请求 `http://localhost:8080/api`，无须手工改文件。

不要直接双击 `index.html` 使用 `file://` 运行，Cookie、CSRF、模块路径和跨域行为会与真实网站不同。

### 3.6 可选：给本机数据库导入演示数据

必须先成功启动一次后端，让 Flyway 建完表；并且数据库仍无用户和商品。然后执行：

```powershell
mysql -u root -p
```

```sql
source D:/newdir/cc/Campus_second-hand_trading_platform/database/seed.sql;
exit;
```

演示账号与 Docker 方式相同。脚本只允许对空业务库执行一次。

## 4. 自动化测试

后端测试：

```powershell
Set-Location backend
mvn test
```

Docker 引擎可用时，Testcontainers 会额外启动真实 MySQL 8.4，验证空库迁移、Hibernate 映射和 Spring Session 表；Docker 不可用时该项会显示跳过，H2 测试仍会运行。

前端检查（从项目根目录执行）：

```powershell
Get-ChildItem frontend/assets/js -Filter *.js | ForEach-Object { node --check $_.FullName }
node frontend/tests/ui-design-contract.test.js
node frontend/tests/session-navigation-race.test.js
```

## 5. 最小验收流程

1. 游客打开首页、搜索商品和用户、查看商品详情。
2. 使用 Alice 登录并发布商品、查看“我的发布”、进入私聊和提交购买意向。
3. 使用 Bob 在另一个无痕窗口登录，验证两个会话不串号，并完成私聊和买卖双方流程。
4. 验证买家提交意向后商品仍然公开；只有卖家选定买家后才进入预留。
5. 使用管理员账号登录，确认管理中心只对管理员显示，普通学生访问管理接口会被拒绝。
6. 退出后刷新受保护页面，确认旧页面不会从本地缓存恢复登录状态。

## 6. 常见问题

### 6.1 Compose 提示变量没有设置

确认已经创建 `deploy/.env`，且 `MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD`、`VERIFICATION_PEPPER`、`PUBLIC_ORIGIN` 均非空。不要修改 `.env.example` 代替本机 `.env`。

### 6.2 端口 80、3306、5500 或 8080 被占用

Docker Web 端口可在 `deploy/.env` 把 `WEB_PORT=80` 改成 `WEB_PORT=8088`，随后访问 `http://localhost:8088`。本机开发需停止占用端口的旧进程或为对应服务换端口，并同步 CORS origin。

### 6.3 后端提示数据库连接失败

确认 MySQL/Docker 容器已启动，密码与当前运行方式一致。本机开发使用 `localhost:3306`；Compose 后端使用服务名 `mysql:3306`，不能把 Compose 内的地址改成 localhost。

### 6.4 后端提示 Flyway 或 Hibernate validate 失败

本项目按“全新数据库”部署。开发环境无保留价值时，删除并重新创建 `campus_secondhand`，再让 Flyway 从 V1 执行。不要开启 `ddl-auto=create` 绕过迁移。

### 6.5 邮箱验证码发送失败

邮件健康不影响网站启动。检查 SMTP 主机、端口、账号、授权码和服务商是否允许 STARTTLS；验证码和 SMTP 密钥不得写入日志或提交到 Git。

### 6.6 Docker 修改代码后页面没有变化

重新构建镜像：

```powershell
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build
```

再使用浏览器强制刷新。只执行 `restart` 不会把新源码复制进旧镜像。

### 6.7 页面显示未登录或写操作返回 403

确认从文档规定的 HTTP 地址访问，不要使用 `file://`；清除旧站点 Cookie 后重新登录。Web 使用服务端 Session 和 CSRF，不能通过 localStorage 或手工填写 userId 模拟身份。

## 7. 正式部署提醒

本文件重点是本地验收。正式部署至少还需要：

- 独立生成数据库密码、pepper 和 SMTP 凭据，不导入演示数据。
- 使用域名 HTTPS，将 `PUBLIC_ORIGIN` 设置为完整 HTTPS origin，并设 `SESSION_COOKIE_SECURE=true`。
- 备份 MySQL volume 和图片 volume，建立恢复演练。
- 由外层反向代理正确清洗转发头并配置 TLS、访问日志和监控。
- 发布前执行 Maven、前端契约和真实 MySQL 8.4 测试。

容器部署的简明命令清单同时维护在 `deploy/README.md`。
