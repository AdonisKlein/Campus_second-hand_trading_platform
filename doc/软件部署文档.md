# 校园二手交易平台部署与运行文档

## 1. 当前运行架构

当前项目已经从旧单体切换为微服务，旧 `backend/` 只保留为课程改造前代码，不再作为运行入口。

当前运行拓扑包括：

- Web：Nginx 静态前端，也是浏览器唯一入口。
- API Gateway：登录 Session、CSRF、安全身份和公开 API 路由。
- Account Service：注册、验证码、登录校验、资料和账号状态。
- Marketplace Service：商品、图片、搜索和公开留言。
- Trading Service：购买意向、订单、私聊、未读和屏蔽。
- Governance Service：举报、治理决定和审计记录。
- MySQL 8.4：同一服务器中的四个独立数据库和四个最小权限账号。
- Redis：保存 Gateway Web Session。
- RabbitMQ：传递交易和治理事件。
- Mailpit：仅用于本地验证码邮件测试。

项目使用 Java 25、Spring Boot 4.0.8、Flyway、Docker Compose 和 Kubernetes/Kind。浏览器继续使用 HttpOnly Session Cookie，不保存内部 JWT。

> 不要提交 `deploy/.env`、`k8s/overlays/ci/.env.secret`、数据库密码、验证码 Pepper、内部令牌或 SMTP 密码。

## 2. 安装与检查工具

### 2.1 日常 Compose 开发需要

- Git
- Docker Desktop（启用 Linux containers）
- PowerShell 7 或 Windows PowerShell 5.1

在新打开的 PowerShell 中检查：

```powershell
git --version
docker version
docker compose version
```

`docker version` 必须同时显示 Client 和 Server。只有 Client 时，应启动 Docker Desktop并等待引擎进入 Running。

### 2.2 Kind 验收额外需要

```powershell
kind version
kubectl version --client
```

GitHub CLI 只用于查看 Actions、PR 和登录 GitHub，不是本地启动项目的必要条件：

```powershell
gh --version
gh auth status
```

安装工具或修改 PATH 后，必须关闭并重新打开 PowerShell、IDE Terminal 和 Codex 桌面应用。若 `gh.exe` 已安装但当前窗口仍提示找不到命令，可先使用完整路径验证：

```powershell
& 'C:\Program Files\GitHub CLI\gh.exe' --version
```

## 3. 方式一：Docker Compose 启动微服务（推荐）

这是日常开发、页面联调和本地注册测试的推荐方式。

### 3.1 创建本机配置

在项目根目录执行：

```powershell
Copy-Item deploy/.env.example deploy/.env
```

生成随机值。下面的表达式每执行一次都会产生一个不同值：

```powershell
[Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

编辑未被 Git 跟踪的 `deploy/.env`，至少填写：

```dotenv
MYSQL_ROOT_PASSWORD=随机值
ACCOUNT_DB_PASSWORD=不同的随机值
MARKETPLACE_DB_PASSWORD=不同的随机值
TRADING_DB_PASSWORD=不同的随机值
GOVERNANCE_DB_PASSWORD=不同的随机值
REDIS_PASSWORD=不同的随机值
RABBITMQ_USERNAME=campus
RABBITMQ_PASSWORD=不同的随机值
INTERNAL_SERVICE_TOKEN=至少32字符的随机值
INTERNAL_JWT_SECRET=至少32字符的随机值
VERIFICATION_PEPPER=至少32字符的随机值
CORS_ORIGINS=http://localhost
SESSION_COOKIE_SECURE=false
WEB_PORT=80
MAIL_ENABLED=false
```

本地脚本要求密码只包含字母、数字、下划线和短横线。不要把中文说明或引号原样保留在实际 `.env` 中。

如果端口 80 已占用，可改为：

```dotenv
WEB_PORT=8088
CORS_ORIGINS=http://localhost:8088,http://127.0.0.1:8088
```

### 3.2 启动带 Mailpit 的完整开发环境

```powershell
powershell -ExecutionPolicy Bypass -File scripts/dev/microservices.ps1 -Action up -Mailpit
```

首次启动会构建六个项目镜像并下载 MySQL、Redis、RabbitMQ、Mailpit 等基础镜像，因此耗时较长。启动完成后执行严格验收：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/dev/microservices.ps1 -Action verify -Mailpit
```

`verify` 会检查：

- MySQL、Redis、RabbitMQ、Gateway、四个业务服务、Web 和 Mailpit 全部 Healthy。
- 四个服务各自的 Flyway 迁移已经执行。
- 四个数据库账号只能访问自己的数据库。
- Gateway liveness 和 Web 首页可以访问。

访问地址：

- 平台：`http://localhost`，使用 `WEB_PORT=8088` 时为 `http://localhost:8088`。
- Mailpit：`http://localhost:8025`。
- Gateway 存活检查：`http://localhost/api/actuator/health/liveness`。

不需要邮件测试时，去掉命令中的 `-Mailpit`。

### 3.3 本地注册与重置密码

Mailpit 会接收验证码邮件但不会投递到公网，因此可以使用任意格式正确、尚未注册的测试邮箱。

1. 打开注册页面。
2. 输入测试邮箱并点击发送验证码。
3. 打开 `http://localhost:8025`。
4. 打开最新验证码邮件并复制 6 位验证码。
5. 回到注册页完成注册。
6. 重置密码时使用相同方式读取 RESET_PASSWORD 验证码。

验证码仍执行生产规则：用途隔离、10 分钟过期、重发和失败次数限制、成功后只能消费一次。数据库只保存 HMAC 摘要。

当前微服务空库不会自动创建演示管理员，也不要导入旧单体的 `database/seed.sql`。普通学生账号应通过注册流程创建。

### 3.4 状态、日志、重建和停止

```powershell
# 查看状态
powershell -ExecutionPolicy Bypass -File scripts/dev/microservices.ps1 -Action status -Mailpit

# 查看所有核心服务日志
docker compose --env-file deploy/.env -f deploy/docker-compose.yml -f deploy/docker-compose.mailpit.yml logs --tail 200 api-gateway account-service marketplace-service trading-service governance-service

# 持续查看某个服务日志；Ctrl+C 只结束日志查看
docker compose --env-file deploy/.env -f deploy/docker-compose.yml -f deploy/docker-compose.mailpit.yml logs -f account-service

# 修改源码后重新构建并启动
powershell -ExecutionPolicy Bypass -File scripts/dev/microservices.ps1 -Action up -Mailpit

# 停止容器，保留数据库、消息、Session 和图片卷
powershell -ExecutionPolicy Bypass -File scripts/dev/microservices.ps1 -Action down -Mailpit
```

不要在需要保留数据时执行 `docker compose down --volumes`。删除 volumes 会永久清除本地四库数据、Redis Session、RabbitMQ 数据、上传图片和 Mailpit 邮件。

直接使用 Compose 的等价启动命令是：

```powershell
docker compose --env-file deploy/.env -f deploy/docker-compose.yml -f deploy/docker-compose.mailpit.yml up -d --build --remove-orphans
docker compose --env-file deploy/.env -f deploy/docker-compose.yml -f deploy/docker-compose.mailpit.yml ps
```

## 4. 方式二：Kind 启动完整 Kubernetes 环境

Kind 方式用于课程验收、Kubernetes 探针和部署流程验证。日常改页面或调接口时优先使用 Compose，因为 Kind 每次需要构建并加载六个镜像。

### 4.1 启动新的微服务集群

为避免与历史的 `campus-ci` 单体集群混淆，推荐使用新名称 `campus-microservices`：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/ci/kind-local.ps1 -Action up -ClusterName campus-microservices
```

脚本会：

1. 构建 Gateway、Account、Marketplace、Trading、Governance 和 Web 镜像。
2. 创建或复用指定 Kind 集群并加载镜像。
3. 生成未提交的随机 Kubernetes Secret。
4. 启动 MySQL、Redis、RabbitMQ 和 Mailpit 并等待就绪。
5. 再启动六个应用，避免依赖未就绪和重叠 rollout。
6. 检查四库权限、Gateway liveness 和 Web 页面。

查看状态：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/ci/kind-local.ps1 -Action status -ClusterName campus-microservices
kubectl --context kind-campus-microservices -n campus-market get pods,svc,pvc
```

预期 MySQL、Redis、RabbitMQ、Mailpit、Gateway、四个业务服务和 Web 共 10 个 Pod 全部为 `1/1 Running`。

### 4.2 访问 Kind 中的平台

端口转发命令会占用当前终端，使用 `Ctrl+C` 停止转发，不会停止集群。

```powershell
# Web 和 API：http://127.0.0.1:18080
powershell -ExecutionPolicy Bypass -File scripts/ci/kind-local.ps1 -Action forward-web -ClusterName campus-microservices

# Mailpit：http://127.0.0.1:18025
powershell -ExecutionPolicy Bypass -File scripts/ci/kind-local.ps1 -Action forward-mail -ClusterName campus-microservices
```

### 4.3 暂停、恢复和删除 Kind 集群

Kind 没有独立的 pause 命令。需要暂时释放 CPU/内存但保留集群数据时，可以停止控制平面 Docker 容器：

```powershell
docker stop campus-microservices-control-plane
docker start campus-microservices-control-plane
```

恢复后等待一会儿，再检查 Pod：

```powershell
kubectl --context kind-campus-microservices -n campus-market get pods
```

确认不再需要集群和其中数据时才执行删除：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/ci/kind-local.ps1 -Action down -ClusterName campus-microservices
```

`down` 会删除整个 Kind 集群以及集群内 PVC 数据，不能通过重新启动容器恢复。

### 4.4 当前机器上的历史 `campus-ci`

历史 `campus-ci` 是旧单体集群，只包含 `campus-backend`、`campus-web`、MySQL 和 Mailpit，不代表当前微服务版本。它可以这样识别：

```powershell
kubectl --context kind-campus-ci -n campus-market get pods
```

停止但保留：

```powershell
docker stop campus-ci-control-plane
```

恢复旧集群：

```powershell
docker start campus-ci-control-plane
```

确定旧数据不再需要时，可永久删除：

```powershell
kind delete cluster --name campus-ci
```

## 5. 在 IDE 中调试单个微服务

五个 Java 工程可以独立构建、测试和启动，默认端口如下：

| 工程 | 端口 |
|---|---:|
| API Gateway | 8080 |
| Account Service | 8081 |
| Marketplace Service | 8082 |
| Trading Service | 8083 |
| Governance Service | 8084 |

单独启动服务需要配置其数据库、内部共享凭据、依赖服务 URI；Gateway 还需要 Redis，交易和治理流程需要 RabbitMQ。具体变量见 `services/README.md`。不要再运行旧 `backend` 作为当前系统，也不要让一个服务使用其他服务的数据库账号。

单服务构建示例：

```powershell
Set-Location services/account-service
mvn verify
```

若要在 IDEA 中调试，推荐先用 Compose 启动依赖，再停止需要调试的那个服务容器，并在 IDEA Run Configuration 中配置同名环境变量后启动该服务。

从项目根目录验证全部 Java 服务：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/ci/verify-services.ps1
```

前端静态测试：

```powershell
Get-ChildItem frontend/tests -Filter *.test.js | ForEach-Object {
    node --test $_.FullName
    if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }

```

## 7. 常见问题

### 7.1 页面无法连接后端

先执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/dev/microservices.ps1 -Action status -Mailpit
docker compose --env-file deploy/.env -f deploy/docker-compose.yml -f deploy/docker-compose.mailpit.yml logs --tail 100 api-gateway
```

浏览器只应访问 Web 暴露的端口，不应直接访问 Account、Marketplace、Trading 或 Governance。

### 7.2 注册发送验证码返回 403

- 必须通过 `http://localhost` 或配置的 `WEB_PORT` 打开页面，不要使用 `file://`。
- `CORS_ORIGINS` 必须与浏览器地址的协议、主机和端口完全一致。
- 清理旧 Cookie 后重新登录或重新获取 CSRF token。
- 确认 Web 请求走 `/api` 同源代理，不要把前端 API 地址手工改成某个内部服务端口。

### 7.3 服务提示数据库连接失败

Compose 内数据库地址是 `mysql:3306`；Kind 内是 `campus-mysql:3306`，不能改成 `localhost`。检查 MySQL health、对应服务的 `DB_PASSWORD` Secret 和 Flyway 日志。

### 7.4 Mailpit 收不到验证码

确认启动命令包含 `-Mailpit`，并检查 Account 日志：

```powershell
docker compose --env-file deploy/.env -f deploy/docker-compose.yml -f deploy/docker-compose.mailpit.yml logs --tail 100 account-service mailpit
```

Mailpit 地址是 `http://localhost:8025`。不使用 Mailpit 时，`MAIL_ENABLED=false` 会让验证码发送明确返回服务不可用。

### 7.5 `gh` 或 `kind` 安装后仍提示找不到

关闭并重新打开当前终端和桌面应用，然后检查 `$env:PATH`。GitHub CLI 默认常见位置为 `C:\Program Files\GitHub CLI\gh.exe`。

### 7.6 Kind rollout 超时

依次检查：

```powershell
kubectl --context kind-campus-microservices -n campus-market get pods,rs
kubectl --context kind-campus-microservices -n campus-market get events --sort-by=.lastTimestamp
kubectl --context kind-campus-microservices -n campus-market describe pod <Pod名称>
kubectl --context kind-campus-microservices -n campus-market logs <Pod名称> --all-containers
```

当前脚本会先等待基础设施，再单次启动应用。若看到同一服务有多个正在运行的 ReplicaSet，应检查是否绕过脚本连续执行了 `apply`、`set image` 和 `set env`。

## 8. 生产环境提醒

- 不导入演示数据，不复用本地 `.env`。
- 使用受保护的 CI Secret 或 Secret Manager 管理数据库密码、Pepper、内部令牌和 SMTP 密码。
- 域名启用 HTTPS，将 `CORS_ORIGINS` 设置为完整 HTTPS Origin，并设置 `SESSION_COOKIE_SECURE=true`。
- 阿里云邮件推送使用已验证发信子域名、SPF/DKIM/DMARC 和独立 SMTP 密码。
- 备份四个数据库、图片存储和消息数据，并定期做恢复演练。
- 发布镜像使用 `sha-<git短提交号>`，禁止只使用 `latest`。
- 所有测试通过后才能构建镜像和部署；部署后必须检查 liveness、readiness 和版本号。

Compose 简明说明见 `deploy/README.md`，Kubernetes 细节见 `k8s/README.md`，单服务变量见 `services/README.md`。
