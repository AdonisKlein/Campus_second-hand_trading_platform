# 校园二手交易平台软件测试文档

## 1. 测试目标

本文定义当前 UC01～UC18 的测试策略、自动化门禁和验收证据。测试重点不是接口返回成功即可，而是同时验证 Session 身份、CSRF、资源归属、状态机和数据库最终状态。

详细需求到测试类的对应关系见《需求追溯矩阵》。本文件不固化某次运行的通过数量；每次验收结果以 Maven、Playwright、CI 报告和 `docs/ai/WORKLOG.md` 中的日期化记录为准。

## 2. 测试环境

| 层级 | 环境与工具 |
| --- | --- |
| 后端单元测试 | Java 25、JUnit 5、Mockito、固定 `Clock`。 |
| API 集成测试 | Spring Boot Test、MockMvc、H2、Spring Security Test。 |
| MySQL 门禁 | Testcontainers `mysql:8.4`、Flyway 空库迁移、Hibernate validate。 |
| 前端静态测试 | Node.js 语法检查、UI 结构契约、Session 竞态回归。 |
| 端到端测试 | Docker Compose、MySQL、Mailpit、Backend、Nginx Web、Playwright。 |
| 部署门禁 | GitHub Actions、候选镜像、Kind/Kubernetes、健康检查与部署证据。 |

## 3. 自动化测试分层

### 3.1 单元测试

单元测试覆盖无需启动完整 Web/数据库环境即可验证的规则：

- `CurrentActorService` 的当前身份、禁用状态和角色检查。
- 验证码用途、失效、尝试次数、消费和发送限流。
- 搜索关键词拆分、数量、价格范围和排序规则。
- 举报治理状态、措施匹配和不可重复处理。
- 测试基础设施和固定时间行为。

### 3.2 API 集成测试

API 测试按业务模块拆分，覆盖成功流程、输入异常、未登录、无 CSRF、角色错误和资源越权：

| 测试类 | 主要覆盖用例 |
| --- | --- |
| `AuthApiIT` | UC01～UC03、UC18 |
| `ProfileApiIT` | UC04、UC18 |
| `ProductApiIT` | UC05～UC09、UC18 |
| `ChatApiIT` | UC10、UC18 |
| `TradingApiIT` | UC11～UC14、UC18 |
| `GovernanceApiIT` | UC15～UC16、UC18 |
| `AdminApiIT` | UC17～UC18 |

API 测试必须直接断言用户、商品、订单、会话、消息、举报和审计记录等数据库最终状态，不能只断言 HTTP 状态码。

### 3.3 MySQL 8.4 并发与迁移门禁

Docker 可用时，`mvn verify` 启动真实 MySQL 8.4 Testcontainers，并验证：

- Flyway 从空数据库执行全部迁移，Spring Session 表存在，Hibernate `validate` 通过。
- 同邮箱并发注册最多成功一次。
- 同一验证码并发消费最多成功一次。
- 多位买家可以分别提交非独占意向；卖家并发接受时最多一条进入 `WAITING_HANDOVER`，商品最多形成一个 `RESERVED`。
- 同一举报并发处理时只能形成一个最终结果和一条有效最终处理链。

不得使用 Hibernate 自动建表代替 Flyway，也不得因为本机 Docker 不可用就把跳过的 MySQL 测试记录为已通过。

### 3.4 前端契约测试

- 所有 `frontend/assets/js/*.js` 必须通过 `node --check`。
- 业务页面不得重新出现宣传横幅、分类侧栏、登录介绍、发布技巧或交易流程教学卡。
- 管理入口必须在 HTML 默认隐藏，仅 ADMIN Session hydration 后显示。
- Session generation 必须防止旧 `/users/me` 响应覆盖登录、退出或 401 后的新状态。
- 受保护操作必须复用 `api.js`，不能从本地用户对象推导身份。

### 3.5 Playwright E2E

核心旅程覆盖：

1. 邮箱验证注册、登录、会话恢复、退出、重置密码和资料修改（UC01～UC04、UC18）。
2. 搜索、上传图片、发布、维护、详情和公开问答（UC05～UC09）。
3. 私聊、未读、屏蔽和学生举报（UC10、UC15）。
4. 购买意向、卖家选择、当面交接和交易工作台（UC11～UC14）。
5. 管理员处理举报以及管理用户、商品和留言（UC16～UC17）。

失败时保存 Playwright HTML、JUnit XML、截图、视频、trace、控制台日志和失败网络请求。测试脚本不得依赖固定种子 ID，管理员确认框等异步交互必须使用原子等待。

## 4. UC01～UC18 验收重点

| 用例 | 必须验证的正向结果 | 必须验证的反向结果 |
| --- | --- | --- |
| UC01 | 验证码注册并建立 Session | 重复邮箱、错误/过期验证码、频率超限不创建账号 |
| UC02 | 登录、恢复和退出状态一致 | 错误密码、禁用账号、失效旧会话被拒绝 |
| UC03 | 新密码生效并撤销旧认证 | 验证码跨用途、重复消费和旧密码失败 |
| UC04 | 本人资料和校园区域更新 | 未登录、非法字段和修改他人资料失败 |
| UC05 | 多关键词交集、筛选、排序和安全投影正确 | 隐私字段不返回，不可售商品不进入结果 |
| UC06 | 图片标准化并发布本人商品 | 非图片、超限、跨 owner 路径和缺少 CSRF 失败 |
| UC07 | 本人编辑、下架和重新上架 | 非 owner、预留/售出、管理员移除时失败 |
| UC08 | 不同身份获得正确详情和动作 | 不可见商品不泄漏，敏感卖家字段不返回 |
| UC09 | 公开留言可读且本人可维护 | 未登录写入、修改他人留言和不可见商品失败 |
| UC10 | 唯一会话、历史、未读和屏蔽正确 | 陌生用户、屏蔽后发送、无权读取失败 |
| UC11 | 创建非独占意向且商品继续在售 | 自购、重复有效意向和伪造买家身份失败 |
| UC12 | 接受一人后形成唯一预留 | 非卖家、过期意向和并发第二次接受失败 |
| UC13 | 买家完成后商品售出 | 非参与者、重复完成失败；取消/超时释放预留 |
| UC14 | 买卖视角、阶段、分组和时间线正确 | 他人订单和账号隐私不返回 |
| UC15 | 合法举报进入本人列表 | 自报、重复、超频和查看他人举报失败 |
| UC16 | 成立/驳回和审计记录正确 | 措施不匹配、普通学生和重复处理失败 |
| UC17 | 管理用户、商品和公开留言 | 非管理员失败，交易状态不被管理操作覆盖 |
| UC18 | 合法 Session + CSRF + 归属请求成功 | 未登录、无 CSRF、伪造 ID、越权和撤权会话失败 |

## 5. 执行命令

```powershell
# 单元、API 集成及 Docker 可用时的 MySQL Testcontainers
cd backend
mvn verify

# 前端结构与会话竞态回归
cd ..\frontend
node --test tests/*.test.js

# 全部 JavaScript 语法
Get-ChildItem assets/js -Filter *.js | ForEach-Object { node --check $_.FullName }

# 变更格式
cd ..
git diff --check
```

完整 Compose E2E 和 Kind 部署由 `scripts/ci/` 与 GitHub Actions 执行；本地运行方式以相关脚本和部署文档为准。

## 6. 通过标准

- 业务规则具有后端测试，权限规则包含反向用例。
- Maven、前端契约测试、全部 JavaScript 语法和 `git diff --check` 通过。
- Docker 可用时，MySQL 8.4 迁移/并发门禁和 Compose E2E 通过；若跳过必须明确记录原因。
- 桌面端和 390px 移动端无整体横向溢出，关键状态有可见反馈。
- 独立审查无未处理 P0/P1。
- 验证日期、命令、结果和遗留项写入 `docs/ai/WORKLOG.md`。
