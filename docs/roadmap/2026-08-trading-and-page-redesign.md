# 交易流程与核心页面重设计路线图

更新日期：2026-08-25

## 已确认的交易流程

校园平台借鉴闲鱼“沟通—下单—履约—确认完成”的分阶段思路，但不接入在线支付和物流：

1. 买家先私聊确认价格、成色、瑕疵和校内交接条件。
2. 买家提交购买意向，商品继续公开在售；同一商品可接收多位买家的意向。
3. 卖家选择一位买家后才形成独占预留，其他待回应意向自动关闭。
4. 双方在私聊中约定校内公共地点，当面验货和交接。
5. 买家确认已取货后交易完成，商品变为已售出。
6. 购买意向、待交接预留可以取消或过期；只有待交接预留释放时才需要让商品恢复在售。

## 第十二轮：商品详情页完整重设计（已完成）

目标：让买家在一个页面内完成“判断商品—了解卖家—沟通—表达购买意向”，不把公开留言、私聊和交易动作混在一起。

- 桌面：左侧图片画廊，右侧价格、成色、标签、区域、卖家卡和交易动作；下方为详情、瑕疵说明、公开问答、同卖家商品。
- 移动：图片优先，底部固定“私聊 / 我想要”操作栏；页面滚动时不遮挡内容和安全区。
- 明确展示商品状态：在售、卖家已选定买家、已售出、卖家下架、管理员下架；不可操作状态保留详情但禁用购买入口。
- “我想要”只提交购买意向，并明确提示不会立即锁定商品；已提交者显示“等待卖家回应”，避免重复提交。
- 卖家卡只展示公开昵称、校园区域、信用、活跃时间和在售数量；不展示邮箱、手机号。
- 公开问答和私聊入口视觉分区；增加安全交易提醒、举报入口、图片失败和空内容状态。
- 需要的后端投影：当前用户对该商品的有效意向、公开卖家摘要、卖家其他在售商品、商品可执行动作。

落地结果：上述布局与投影均已实现；现阶段每件商品只有一张平台受控图片，多图排序仍按“后续页面”的发布/编辑轮次实施。

## 第十三轮：订单管理页完整重设计（已完成）

目标：不再把所有记录平铺成相同卡片，让买家和卖家快速找到当前需要处理的事情。

- 一级切换：“我买到的 / 我卖出的”；二级状态：“待回应 / 待当面交易 / 已结束”。
- 卖家视角按商品分组展示全部购买意向，可比较买家公开信用、区域、意向时间，并明确“选定该买家 / 暂不接受”。
- 买家视角使用时间线展示：已提交意向 → 卖家选定 → 约定见面 → 确认取货；未被选中要显示具体关闭原因。
- 待办优先排序，展示剩余有效时间；到期后按钮立即消失，不能依靠点击失败表达状态。
- 每笔记录提供“查看商品 / 私聊对方 / 取消 / 举报”；危险操作使用页面内确认框，不使用浏览器 `alert`。
- 订单详情采用侧滑面板或独立页，显示商品与价格快照、双方昵称快照、状态历史和操作说明。
- 需要的后端 interface：按角色/状态分页、商品意向分组、服务端返回 `allowedActions`、状态时间线和关闭原因。

落地结果：已实现买入/卖出视角、阶段统计与筛选、商品意向分组、安全买家摘要、有效状态、时间线、关闭原因、剩余时间、详情抽屉和页面内确认；当前数据量阶段一次最多读取当前用户的订单集合，正式大数据量前再在同一 interface 下增加游标分页。

## 第十四轮：个人中心完整重设计

目标：把个人资料、交易资产和账户安全分层，避免所有表单堆在同一页面。

- 顶部身份卡：头像/昵称、学校验证状态、校园区域、信用分、最近活跃。
- 快捷统计：在售、购买意向、待交接、未读消息、收藏；点击进入对应筛选结果。
- 功能分区：我发布的、我买到的、我卖出的、消息、收藏与关注、举报记录。
- 设置分区：公开资料、校园区域、登录邮箱、密码与全部设备退出；敏感资料默认不展示。
- 管理员登录后不混入学生交易入口，个人中心提供独立“进入管理中心”。
- 桌面采用资料概览 + 内容区；移动采用卡片列表和独立编辑页，保存过程有 loading、成功提示和错误恢复。
- 本轮同时规划收藏/关注的数据结构，但不得让统计卡出现尚不可用的假入口。

## 第十五轮：私聊页面完整重设计

目标：让买卖双方围绕具体商品完成沟通、报价和当面交易协商，聊天页既像即时消息工具，也始终保留商品与交易上下文。

- 桌面采用“会话列表 + 当前聊天 + 商品/交易信息”三段式布局；移动端使用会话列表与聊天房间两级页面，返回路径清晰且适配安全区。
- 会话列表支持关键词搜索、未读优先、按最近消息排序，并清楚展示商品缩略信息、对方昵称、最后消息、未读数和交易状态。
- 聊天房间按日期分段，区分自己和对方的消息；补齐发送中、失败重试、空会话、断线重连和历史消息加载状态。
- 顶部固定商品上下文卡，可查看商品详情、当前价格和状态；商品下架、已预留、已售出时仍保留历史会话并给出明确提示。
- 增加结构化报价卡：买家填写报价和简短说明，卖家接受后按该价格形成购买意向；普通文本不能被误识别为报价。
- 提供交易安全提醒、拉黑与举报入口；管理员仍不能读取学生私聊正文，只能处理用户主动提交的举报证据。
- 未登录点击私聊时先在当前页弹出说明，用户确认后再跳转登录；已有会话可从商品详情、订单工作台和个人中心准确回到对应聊天。
- 需要的后端 interface：会话摘要分页、游标消息分页、幂等发送、结构化消息类型、报价状态机、未读游标与会话级权限。

## 后续页面

- 发布/编辑商品：多图排序、瑕疵结构化描述、价格建议、预览后发布。
- 管理中心：举报、商品、用户、订单分工作台；管理员仍不能读取学生私聊正文。

## 每轮完成门禁

- 桌面 1440px、平板 768px、移动 390px 和 320px 均无横向溢出或不可达操作。
- 页面状态由后端 interface 返回，不在前端复制交易规则。
- 游客、学生买家、学生卖家、管理员分别做正向和反向权限用例。
- H2 与真实 MySQL 8.4 迁移/集成测试通过，Docker 双账号业务流通过。
- 同步 Postman、用户手册、测试文档、`docs/ai/PROJECT_CONTEXT.md` 和 `WORKLOG.md`。
